# ALPS ALPINE Engineering Twin Workbench — 시스템 문서

**버전 v1.0 · 2026-09-15 기준 · 전체 개발 기능 총정리**

본 문서는 워크벤치에 현재 구현된 모든 기능·화면·특징과, 기존 솔루션 대비 차별점, Alps Alpine에서의 활용 가능성, 향후 발전 방향을 정리한 시스템 참조 문서이다. 앱 내 **시스템 문서 탭**에서 언제든 열람할 수 있고, `.md` 파일로 다운로드해 회의 부착·보고·온보딩 자료로 바로 사용할 수 있다.

> **정직성 원칙 (이 시스템의 설계 철학)** — 화면의 모든 교육용 추정치에는 △ educational estimate, 합성 데이터에는 ◇ synthetic fixture 배지가 붙는다. 브라우저 내 목(mock) 실행 결과는 절대 사인오프 증적이 될 수 없으며, 게이트 JSON에는 `MOCK_RESULT_PRESENT` 블로커가 항상 표시된다. 승인된 증적은 덮어쓰지 않고 신규 리비전만 생성된다. 상태는 색 단독이 아니라 아이콘+문구로 표시된다. 본 문서의 기능 서술도 이 원칙을 따른다.

---

## 1. 시스템 개요

**ALPS ALPINE Engineering Twin Workbench**는 요구사항 정의 → 3D 설계 검토 → 시뮬레이션 → 실측 상관 → 게이트 심사 → 양산 품질까지의 제품 엔지니어링 전 주기를 **하나의 웹 워크벤치**에서 관리하는 엔지니어링 디지털 트윈 플랫폼이다. 여기에 (1) IC 설계·회로 테스트를 학습하는 **EDA 교육 모듈**, (2) Alps Alpine의 ASIC 개발 9단계를 게이트·증적 중심으로 진행하는 **ASIC 9단계 작업 센터**, (3) 정전식 3D 감지 필드를 해석하는 **AirInput Field Twin** 이 더해져 "기계·회로·공정·품질"을 한 화면에서 다룬다.

```
요구사항(S03) → 3D 설계검토(S04) → 개발/테스트 보드(S05) → 시스템 모델(E02)
     ↕                    ↕                     ↕                  ↕
  프로세스 트윈(TS03–05) · AirInput Field Twin · EDA 교육 · ASIC 9단계 작업 센터
     ↘ 결과 비교(S08) · SWEEP 변량 비교 · 테스트 상관(S09) · 게이트(S10) ↙
```

## 2. 시스템 아키텍처

| 계층 | 기술 | 비고 |
|---|---|---|
| 프런트엔드 | React 19 + TypeScript + Vite | SPA, 제품/변량 상태는 zustand 스토어 |
| 3D 렌더링 | react-three-fiber 9 + three 0.186 (WebGL) | **웹 네이티브 3D — Unity 등 외부 런타임 불필요** |
| 국제화 | i18next (한국어·English·日本語) | 타입 안전 3-로케일 동기 |
| 인증 | Keycloak (OpenID Connect) | 역할 기반(예: demo.architect — Approver), 로그아웃/SSO |
| 백엔드 | FastAPI (Python) | 요구사항·부품·시뮬레이션 런·게이트 REST API |
| 워크플로 | Temporal | 시뮬레이션 파이프라인의 장기 실행·재시도 |
| DB | PostgreSQL | 제품·변량·런·증적 메타데이터 |

3D 장면(부품 지오메트리, 파장·파형, 패키지 단면, 공정 플로우)은 전부 서버 설치가 필요 없는 브라우저 렌더링이며, 시뮬레이션 교육 러너(lint/시뮬레이션/합성/P&R)는 결정론적 시드(mulberry32)로 재현 가능한 결과를 낸다.

## 3. 화면·기능 전체 목록

### 3.1 통합 내비게이션 바 (전 화면 공통)

- **한 줄 위계**: `PRODUCT ▸ VARIANT` 선택 → `VIEWS`(제품 트윈 뷰) → `STANDALONE MODULES`(독립 모듈) → 언어 전환.
- 모든 컨트롤이 동일한 높이·라운딩·폰트와 micro-caption을 공유하는 단일 컨트롤 체계.
- 독립 모듈(EDA 교육·ASIC 센터·시스템 문서) 진입 시 제품/변량 셀렉트가 흐려지며 비활성화되고 "ⓘ 독립 모듈은 제품/변량 선택과 무관" 힌트 표시 — **UI가 거짓말을 하지 않는다**.
- 좌우 사이드 패널·하단 비교/상관/게이트 프레임이 접히는 **포커스 모드**로 독립 모듈에 전폭을 제공.
- 온보딩 가이드("Where you are")가 진행 상황을 체크리스트로 안내.

### 3.2 Requirements & Trace (S03)

- 요구사항 목록: 안전 등급(ASIL/QM), 상태(Test/Draft), 우선순위, 검증 항목(VER) 연결.
- 요구사항 ↔ 부품 트레이스: 요구사항 클릭 → 3D 뷰에서 해당 부품 하이라이트(양방향 연동).
- Req→Ver 커버리지 %, 미해결 컨플릭트 카운트.

### 3.3 3D Design Review (S04)

- CAD 개념 3D 뷰어: 부품별 클릭 선택 ↔ 요구사항 역조회.
- **폭발도(Exploded view)** 슬라이더, **X-ray(바디 투과도)** 슬라이더.
- 조립 시뮬레이션 재생: 사이클 슬라이더로 누름 동작·차량 진동 프레임 재생.
- 응력 핫스팟 표시(교육용 시각화임을 명시 — 수명 예측 아님).

### 3.4 Dev/Test Board (S05)

- 가상 테스트 벤치: 누름 스위치/차량 진동 입력 → 실측(합성) 데이터 채널 표시.
- 예측 모델 결과와의 나란히 비교(Result Compare, S08).

### 3.5 System Model (E02)

- 시스템 블록 모델 뷰: 입력→처리→출력 체인과 신호 흐름.
- 예측 모델(analytical-mech-model 등) 파라미터와 결과 메트릭.

### 3.6 Process Twin (TS03–05)

- 제조 공정 트윈: 공정 단계·모니터링 차트(§5.1 범례 규칙 준수).
- **3D 팹 플로우 뷰**: 웨이퍼→프론트엔드→패키징 공정 흐름을 3D로 시각화.

### 3.7 AirInput Field Twin (3D) — 정전 감지 특화 모듈

- **손가락·장갑·표면·전극·접지판의 3D 모델**과 전기장 슬라이스 히트맵.
- **이원화 해석 계층**: 유한차분 라플라솔버(FD, 참조 정밀 해) ↔ RBF 서로게이트(실시간 클라이언트 평가, OOD 영역 플래그).
- 전극별 정전용량(ΔC) 곡선, 감지영역/데드존/오검출 히트볼 볼륨.
- **ASIC ↔ 알고리즘 판정 체인**: v1 고정임계값 vs v2 베이스라인-히스테리시스(IDLE/NEAR/TOUCH, 디바운스) 비교.
- Robot Scan 예측-실측 검증, GOLD-01..06 시나리오 테이블, Surrogate/Solver 티어 패널.

### 3.8 EDA Training (IC Design & Circuit Test)

- Lint → 회로 시뮬레이션(파형 뷰어) → 합성 → Place&Route 3D의 EDA 플로우 체험.
- 미션: 4비트 카운터, 4비트 ALU, 동기 FIFO, UART TX, **32비트 RISC**(544 FF).
- 합성 결과 KPI(FF/LUT 수), 레이아웃 3D(레이어 칩·폭발도), 교육용 파형.

### 3.9 ASIC Program — 9단계 작업 센터 (지시서 v1.0 §2 매핑)

| 단계 | 화면 내용 | 핵심 게이트 |
|---|---|---|
| ① 요구사양 검토 | 요구 매트릭스, AI 제안으로 draft 링크·검증항목 생성 | REQ_TRACE_100 |
| ② 타당성·아키텍처 | 공정/패키지 옵션 승인(OPT), 리스크·리드타임 | OPT_CONFIRMED |
| ③ 프로그램 베이스라인 | 베이스라인 전자서명 | BASELINE_SIGNED |
| ④ ASIC 설계 | Lint/시뮬레이션/합성/P&R 실행(EDA 러너 재사용) | DESIGN_COMPLETE |
| ⑤ 엔지니어링 샘플 | **패키지 3D 트윈**(다이·본딩와이어·몰드·납땜·MEMS) + 실측-예측 상관(R², bias/MAE/RMSE) | CORRELATION_OK |
| ⑥ ECO·테스트 프로그램 | 변경 영향 분석 → ECO 클로즈 → **마스크/테스트프로그램 리비전 증가 + 증적 재승인 강제**(§14.3) | ECO_CLOSED |
| ⑦ CS·양성 신뢰성 | AEC-Q100 Grade별 온도 조건 테이블(`alps-asic-v1.0` 정책), 증적/CAPA/웨이버 | QUAL_PASS |
| ⑧ 릴리즈·증적 | 증적 전자서명, readiness ladder(education_only→released), 게이트 JSON | EVIDENCE_APPROVALS |
| ⑨ 양산 | 로트 SPC·파레토, 불량 로트 MRB 처분, 출하 | LOT_RELEASE |

- 4개 제품 템플릿(캡 터치 AFE/전류센서/모터 리플/환경센서) × 서로 다른 게이트 상태·미션·상관 파라미터.
- 스테이지 코트핀: 진행 단계 n/9, 다음 게이트, 커버리지, 양성률, R²를 한눈에.
- 게이트 JSON이 블로커(`MOCK_RESULT_PRESENT`, `EVIDENCE_APPROVALS` 등)와 `decision_required`를 정직하게 출력 — **릴리즈는 가짜로 찍히지 않는다**.

**v1.1 고도화 (백엔드 연동 — 지시서 v1.1 §4/§7/§8, 전류 센서 ASIC PoC)**

- **신호체인 리비전 (EPIC A)**: r1→r2 승격은 수정이 아니라 새 리비전 생성 + 이전 리비전 supersede(불변규칙). 블록별 오류예산 테이블과 content_hash를 ②③ 단계에 표시.
- **Corner/MC 해석 (EPIC A)**: 시드 고정된 오류예산 전파 몬테카를로 → P50/P95/P99·규격 이탈률 + **실제 표본 24-bin 히스토그램**. 시험 온도가 보정 범위를 벗어나면 MODEL OOD 배지. 같은 시드 = 동일 결과(재현성 §12).
- **장비 실측 임포트 (EPIC E)**: 테스터 CSV 원본 바이트를 파싱 전 sha256 아티팩트로 승격. **같은 파일은 절대 두 런을 만들지 않는다**(409). 부분 파일·시간역전·중복 블록은 findings로 기록(무음 수정 금지 §7). 교정 만료는 데이터로 저장되고 게이트에서 블로커가 된다.
- **양성 매트릭스 + 폐루프 (EPIC F·G)**: AEC-Q100 그룹별 최신 행 판정(latest row per group). 실패 행은 FA 케이스로 처분 — RCA 승인은 **인간 전담 역할만**, 관찰 사실 + 확인 증적 없이면 422. ECO는 회귀 증적 + 검증 측정런 없이 종결 시 412. 종결 시 FA가 verified로 폐루프.
- **기능안전 트레이스**: SG→FSR→TSR→HW 트리 + FMEDA(분포·DC·FIT·소스 해시) + 고장주입(기대/관찰)을 ⑦ 단계에 렌더링.
- **게이트 정책 `alps-asic-v1.1`**: 신규 블로커 `CALIBRATION_EXPIRED`·`MODEL_OOD`·`MIXED_REVISION_EVIDENCE`·`QUAL_FAILURE_OPEN`·`WAIVER_EXPIRED` + 불변의 `MOCK_RESULT_PRESENT`. Readiness Ladder 6단계(education_only→…→controlled_pilot 도달, production_candidate/released는 미도달). **게이트 리포트는 서버 값을 그대로 렌더링** — UI가 블로커를 만들어내지 않는다.
- 쓰기 전부 역할 게이트(임포트=시험, RCA=전력 ASIC/품질, ECO 종결=아키텍트/승인자). 백엔드 한국어 데모 문자열은 렌더 시점 l10n 오버레이로 en/ja 표시.

### 3.10 결과 비교·상관·게이트 (하단 프레임)

- **SPICE Resistance Sweep — Variant Compare (S08)**: 변량 2개 이상을 동일 축·동일 단위로 중첩 비교(§12.2).
- **Test & Correlation (S09)**: 예측 모델 vs 실측 상관 표.
- **Gate (S10)**: 게이트 제출/심사 상태.
- **Assistant**: LLM 어시스턴트 패널(질의·화면 안내).

### 3.11 시스템 문서 탭 (본 문서)

- 본 문서를 앱 내에서 렌더링 열람 + `.md` 다운로드 버튼(보고·온보딩 부착 자료).
- 제품/변량 컨텍스트와 무관한 독립 참조 메뉴.

## 4. 특징과 장점

| 특징 | 설명 | 장점 |
|---|---|---|
| 전 주기 단일 워크벤치 | 요구사항→설계→검증→양산 증적이 하나의 맥락 | 도구 간 복사·수작업 보고서 제거, 추적 가능성 상승 |
| 정직한 데이터 계층 | 교육용 추정/합성 픽스처 배지, 목 결과 사인오프 차단, 증적 불변(신규 리비전만) | 학습·데모 데이터가 실제 판단에 오염되지 않음 — 감사 대응의 기초 |
| 웹 네이티브 3D | WebGL(r3f) 기반, 설치·플러그인 불필요 | 누구나 브라우저로 즉시 검토, 배포 비용 최소 |
| 변량·제품 스케일 | 제품×변량 템플릿 구조, 동일 축 비교 | 파생 모델 관리 비용 감소 |
| 결정론적 재현 | 시드 기반 러너, 상태 머신형 게이트 | 재현 가능한 교육·회귀 테스트 |
| 3-로케일 UI | 한/영/일 완전 동기 | 일본 본사–한국–해외 거점 동시 사용 |
| SSO·역할 승인 | Keycloak, 전자서명형 승인(approver 기록) | 감사 추적과 책임 소재 명확화 |

## 5. 기존 솔루션 대비 차별점

| 비교 대상 | 기존 방식의 한계 | 본 시스템의 차별점 |
|---|---|---|
| 전통적 PLM(문서 중심) | 3D·시뮬레이션·판정이 툴마다 분산, 문서 등록이 목적 | **라이브 트윈 + 증적 체인 통합** — 보는 화면이 곧 증거 |
| 단독 시뮬레이터(SPICE/FEM 툴) | 결과가 워크벤치 밖 파일로 존재, 요구사항과 단절 | 런 결과가 요구사항·게이트·상관 패널과 즉시 연결 |
| Unity 등 게임엔진 디지털 트윈 | 런타임 설치·라이선스·웹 배포 부담, IT 협의 필요 | 웹 표준만으로 3D 구현 — **Unity 종속 없음**(지시서 요건 충족) |
| Excel/메일 기반 ASIC 진행 관리 | 단계·게이트·증적·ECO 상태가 사람 머리에 존재 | 9단계 작업 센터가 게이트·블로커·증적 리비전·ECO를 한 화면에서 강제 |
| 사내 교육(문서+시험) | 실습 환경 부재, 실 장비 오조작 위험 | **실 사인오프와 물리적으로 분리된** 교육 모듈(EDA·ASIC) |
| 범용 BI 대시보드 | 상태 표시만 가능, 행동 유도 불가 | 각 지표에서 바로 다음 액션(승인·MRB·ECO)으로 이어지는 워크 플로우 |

핵심 차별점은 **"정직성이 시스템에 내장"** 되어 있다는 점이다 — 교육/데모용 결과가 실제 릴리즈 판단으로 흐르는 경로를 구조적으로 차단(`MOCK_RESULT_PRESENT` 불변 블로커, 도달 불가 readiness 레벨 ✕ 표시, 승인 증적 불변 규칙)하므로, 시연용 환경과 실무 게이트가 같은 도구 안에 공존할 수 있다.

## 6. Alps Alpine에서의 활용 가능성

1. **제품 포트폴리오 1:1 템플릿** — 택트 스위치, 근접/에어인풋 센서, 전류센서, 모터 리플, 환경센서, 캡터치 AFE ASIC이 이미 템플릿으로 존재. 신규 제품은 템플릿 복제로 진입.
2. **부서 간 단일 화면** — 영업(요구사항), 설계(3D·EDA), 품질(게이트·MRB·SPC), 생산(프로세스 트윈)이 동일 데이터를 보며 각자의 뷰로 작업.
3. **ASIC 수탁/자체 개발 관리** — 9단계 작업 센터로 고객·협력 파운드리와의 단계별 증적(스펙 베이스라인, ES 상관, ECO 리비전, AEC-Q100 인증)을 추적.
4. **신입/이직 엔지니어 온보딩** — EDA 교육(조합·순차·프로토콜·RISC 미션)과 ASIC 9단계 시뮬레이션으로, 실개발 데이터를 건드리지 않는 안전한 실습.
5. **고객 검토회 자료** — 3D 폭발도·파형·상관 그래프를 브라우저에서 즉시 시연, 컨피덴셜 분류 표시로 정보 등급 관리.
6. **교육→실무 전환 경로** — 교육 모듈에서 익힌 러너·게이트 개념이 실무 작업 센터와 동일 UI라 학습 비용 최소.

## 7. 향후 발전 방향

| 방향 | 내용 | 우선순위 |
|---|---|---|
| 실데이터 연계 | 교육용 지오메트리→실 CAD, 합성 실측→실 측정기/데이터 로거 연결 | 상 |
| EDA 실연동 | 오픈소스 툴체(Yosys/nextpnr 등) 또는 상용 툴 래퍼 연결, 목 러너 단계적 치환 | 상 |
| 커넥터 | PLM·요구사항 관리(예: JAMA 계열)·MES/QMS 연동, §13.2 AI 이상탐지 알림(홀드는 외부 QMS 유지) | 중 |
| 서로게이트 고도화 | AirInput RBF→심층 서로게이트, DOE 자동화, OOD 정교화 | 중 |
| 협업 기능 | 코멘트·스크린샷 공유, 리뷰 세션(화면 동기), 승인 라우팅 규칙 엔진 | 중 |
| 배포·접근성 | 모바일/태블릿 최적화, 오프라인 리뷰 패키지(증적+3D) 내보내기, WCAG 접근성 | 중 |
| 문서 자동화 | 본 시스템 문서의 다국어 자동 생성, 증적 기반 보고서 추출 | 하 |

> 현재 제약(정직하게 밝힘): 3D 지오메트리·측정값·EDA 러너는 교육용 합성이며, 시뮬레이션 결과는 사인오프 등급이 아니다. 위 실데이터 연계 항목이 완료되어야 readiness ladder의 상위 레벨(released)이 비로소 도달 가능해진다 — 이는 버그가 아니라 설계다.
