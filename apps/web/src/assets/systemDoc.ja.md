# ALPS ALPINE Engineering Twin Workbench — システムドキュメント

**バージョン v1.3 · 2026-09-23時点 · 全開発機能総まとめ**

本文書は、ワークベンチに現在実装されているすべての機能・画面・特徴と、既存ソリューションとの差別化ポイント、Alps Alpineでの活用可能性、今後の発展方向を整理したシステムリファレンスドキュメントである。アプリ内の**システムドキュメントタブ**(adminアカウントログイン時に表示)から閲覧でき、`.md`ファイルとしてダウンロードして会議資料・報告・オンボーディング資料としてそのまま使用できる。

> **誠実性の原則(本システムの設計思想)** — 画面上のすべての教育用推定値には△ educational estimate、合成データには◇ synthetic fixtureバッジが付く。ブラウザ内モック実行結果は絶対にサインオフエビデンスにはならず、ゲートJSONには`MOCK_RESULT_PRESENT`ブロッカーが常に表示される。承認済みエビデンスは上書きせず新規リビジョンのみ生成する。ステータスは色単独ではなくアイコン+文言で表示する。本文書の機能記述もこの原則に従う。

>
> **v1.1 (2026-09-17) 主な更新** — プレミアム計器UI(デザイントークン・エンボスシェル・プレミアムグラフテーマ)、アプリ全体のダーク/ライトテーマ切替(計器3D・オシロのガラスはダーク維持、両モードでWCAGコントラスト監査CLEAN)、言語切替のヘッダー右上固定、3Dコックピットランディング(modelタブ)、生産ライン3Dツイン(FactoryViewer)、3D設計レビューツール(断面/計測/注釈)、全パネル部品ID選択同期、ASICパッケージファミリー3Dモデル・ボンドマップ1:1ファンアウト・Auワイヤのリアル調描画、EDAミッション・3Dシーンの自社チップセット化、AirInput専用テストベンチボード(puckモジュールDUT)。

## 1. システム概要

**ALPS ALPINE Engineering Twin Workbench**は、要求定義 → 3D設計レビュー → シミュレーション → 実測相関 → ゲート審査 → 量産品質までの製品エンジニアリング全周期を**1つのWebワークベンチ**で管理するエンジニアリングデジタルツインプラットフォームである。そこに(1) IC設計・回路テストを学ぶ**EDA研修モジュール**、(2) Alps AlpineのASIC開発9段階をゲート・エビデンス中心に進める**ASIC 9段階ワークセンター**、(3) 静電容量3D検知フィールドを解析する**AirInput Field Twin**が加わり、「機械・回路・工程・品質」を1画面で扱う。

```
要求(S03) → 3D設計レビュー(S04) → 開発/テストボード(S05) → システムモデル(E02)
     ↕                    ↕                     ↕                  ↕
  プロセスツイン(TS03–05) · AirInput Field Twin · EDA研修 · ASIC 9段階ワークセンター
     ↘ 結果比較(S08) · SWEEPバリアント比較 · テスト相関(S09) · ゲート(S10) ↙
```

## 2. システムアーキテクチャ

| レイヤー | 技術 | 備考 |
|---|---|---|
| フロントエンド | React 19 + TypeScript + Vite | SPA、製品/バリアント状態はzustandストア |
| 3Dレンダリング | react-three-fiber 9 + three 0.186 (WebGL) | **Webネイティブ3D — Unity等の外部ランタイム不要** |
| 国際化 | i18next (韓国語·English·日本語) | 型安全3ロケール同期 |
| 認証 | Keycloak (OpenID Connect) | ロールベース(例: demo.architect — Approver)、ログアウト/SSO |
| バックエンド | FastAPI (Python) | 要求・部品・シミュレーションラン・ゲートREST API |
| ワークフロー | Temporal | シミュレーションパイプラインの長期実行・リトライ |
| DB | PostgreSQL | 製品・バリアント・ラン・エビデンスメタデータ |

3Dシーン(部品ジオメトリ、波動・波形、パッケージ断面、工程フロー)はすべてサーバーインストール不要のブラウザレンダリングであり、シミュレーション研修ランナー(lint/シミュレーション/合成/P&R)は決定論的シード(mulberry32)で再現可能な結果を出す。

## 3. 画面・機能 全体リスト

### 3.1 統合ナビゲーションバー (全画面共通)

- **1行のヒエラルキー**: `PRODUCT ▸ VARIANT`選択 → `VIEWS`(製品ツインビュー) → `STANDALONE MODULES`(独立モジュール)。言語切替とダーク/ライトテーマトグルは**ヘッダー右上に固定** — どの画面からでも常にアクセス可能。
- すべてのコントロールが同一の高さ・角丸・フォントとmicro-captionを共有する単一コントロール体系。
- **プレミアム計器デザイン**: `--alps-*`デザイントークン、エンボスボタン・メタリックパネルシェル、プレミアムECharts/SVG/canvasグラフテーマを全画面に一貫適用。アプリ全体の**ダーク/ライトテーマ切替**(計器3D・オシロのガラスはダーク維持)を備え、両モードともWCAGコントラスト監査CLEAN。
- 独立モジュール(EDA研修・ASICセンター・システムドキュメント)に入ると製品/バリアントセレクトが薄まり無効化され、「ⓘ 独立モジュールは製品/バリアント選択と無関係」ヒント表示 — **UIは嘘をつかない**。
- 左右サイドパネル・下部比較/相関/ゲートフレームが折りたたまれる**フォーカスモード**で独立モジュールに全幅を提供。
- オンボーディングガイド(「Where you are」)が進捗をチェックリストで案内。

### 3.2 Requirements & Trace (S03)

- 要求リスト: 安全等級(ASIL/QM)、ステータス(Test/Draft)、優先度、検証項目(VER)接続。
- 要求 ↔ 部品トレース: 要求クリック → 3Dビューで該当部品ハイライト(双方向連動)。
- Req→Verカバレッジ%、未解決コンフリクト数。

### 3.3 3D Design Review (S04)

- CADコンセプト3Dビューア: 部品クリック選択 ↔ 要求逆引き。
- **3Dコックピットランディング**: modelタブでは3Dビューが全幅を占め、ガラスHUDストリップ(製品・バリアント | ゲート準備度GateDot | 最新シミュレーションラン | 要求↔部品リンクチップ)がキャンバス上に浮く。要求/シミュレーションパネルは折りたたみ式ガラスドロワーに退避。
- **レビューツールバー (FR-03)**: 断面クリッピング(軸・オフセット)、2点間距離計測(mm、STEP単位)、アノテーションピン(◈ クライアントローカル表記)。ツールバーをOFFにすれば基本画面はクリーンなまま。
- **全パネル部品ID同期 (指示書L187)**: 3D・回路検証行・システムモデルノードが同じ部品IDで同時ハイライト(逆方向も含む)。
- **爆発図(Exploded view)**スライダー、**X-ray(ボディ透過度)**スライダー。
- 組立シミュレーション再生: サイクルスライダーで押し動作・車両振動フレーム再生。
- 応力ホットスポット表示(教育用可視化であることを明記 — 寿命予測ではない)。

### 3.4 Dev/Test Board (S05)

- **ファミリー別DUTモジュール**: ベンチPCB上に製品ファミリー別のDUTが実装される — タクト(押しスイッチ)、エンコーダ(スリットディスク)、MEMS(圧力ゲージ)、AirInput(電極puckモジュール)。
- 2チャンネルオシロスコープ(実信号チェーン状態マシン、RUN/STOP・ベゼルLED)+ F–Sカーブオーバーレイカーソル同期。
- **AirInput puckボード**: ハウジング・PCB・電極(バリアントA円形パッド/Bスプリットリング)・カバーガラス・キャステレーション端子を実装し、指先スティミュラス(接近/離隔)でスコープCH1検知レベル・CH2タッチヒステリシスコンパレータ・ボードLEDが反応。
- **Circuit Testテーブル**: 実SPICEラン結果(出所チップ: business_id · tool_version)と並列比較(Result Compare、S08)。
- ベンチDUTは選択部品と種別が一致する時のみエミッシブハイライト — 不一致時は「ベンチDUT=製品全体」の誠実チップを表示。

### 3.5 System Model (E02)

- システムブロックモデルビュー: 入力→処理→出力チェーンと信号フロー。
- 予測モデル(analytical-mech-model等)パラメータと結果メトリクス。

### 3.6 Process Twin (TS03–05)

- 製造工程ツイン: 工程ステップ・モニタリングチャート(§5.1凡例ルール準拠)。
- **3Dファブフロービュー**: ウェハー→フロントエンド→パッケージング工程フローを3D可視化。
- **生産ライン3Dツイン (FactoryViewer)**: 工程順(seq_no)に配置されたステーション3Dラインが管理状態色(正常/注意/逸脱/待機)で発光し、ステーションをクリックすると該当管理チャート・キャビティドリフト・ロット詳細ドロワーが開く。コンベアドットはロットdisposition色。
- リアル調設備シルエット(環状灯・プレス・成形機・ロボットセル)+状態凡例・OOWカウンタ・DOEスクロールHUD。

### 3.7 AirInput Field Twin (3D) — 静電容量検知特化モジュール

- **指・手袋・表面・電極・接地板の3Dモデル**と電界スライスヒートマップ。
- **二層化解析レイヤー**: 有限差分ラプラスソルバー(FD、参照精密解) ↔ RBFサロゲート(リアルタイムクライアント評価、OOD領域フラグ)。
- 電極別静電容量(ΔC)カーブ、検知領域/デッドゾーン/誤検出ヒートボリューム。
- **ASIC ↔ アルゴリズム判定チェーン**: v1固定閾値 vs v2ベースライン-ヒステリシス(IDLE/NEAR/TOUCH、デバウンス)比較。
- Robot Scan予測-実測検証、GOLD-01..06シナリオテーブル、Surrogate/Solverティアパネル。
- **バリアント追従電極ジオメトリ**: バリアントA(円形パッド)/B(スプリットリング)の電極形状がソルバー・CAD・ビューア・テストベンチpuckで同一電極中心座標に一致 — タブ間のモデル不一致なし。

### 3.8 EDA Training (IC Design & Circuit Test)

- Lint → 回路シミュレーション(波形ビューア) → 合成 → Place&Route 3DのEDAフロー体験。
- ミッション5種は自社製品チップセット風味: タクトデバウンスカウンタ、タッチALU、AFEサンプルFIFO、センサーUART TX、**AFE SoC 32ビットRISC**(544 FF) — `silProfileOf`が製品テンプレート別チップセットプロファイルを付与。
- 合成結果KPI(FF/LUT数)、レイアウト3D(レイヤーチップ・爆発図)、教育用波形。
- **3Dシーン3種(プロセス/合成/レイアウト)**: 合成シーンは標準セルロー・M1レール・Cu/Al配線・Auビア・シールリングまでリアル調で描画。

### 3.9 ASIC Program — 9段階ワークセンター (開発指示書v1.0 §2マッピング)

| 段階 | 画面内容 | 主要ゲート |
|---|---|---|
| ① 要求仕様検討 | 要求マトリクス、AI提案でdraftリンク・検証項目生成 | REQ_TRACE_100 |
| ② 実現性・アーキテクチャ | プロセス/パッケージオプション承認(OPT)、リスク・リードタイム | OPT_CONFIRMED |
| ③ プログラムベースライン | ベースライン電子署名 | BASELINE_SIGNED |
| ④ ASIC設計 | Lint/シミュレーション/合成/P&R実行(EDAランナー再利用) | DESIGN_COMPLETE |
| ⑤ エンジニアリングサンプル | **パッケージ3Dツイン** — テンプレートオプションからパッケージファミリー(QFN/WLCSP/LGA/SOIC/LQFP)モデルをパース、ボンドマップ1:1ファンアウト、**Auボンドワイヤ**(ボール/スティッチボンド→銀メッキフィンガー)、センサー積層/キャビティ集積、エクスプロードアンカー・モールドオフビュー + 実測-予測相関(R²、bias/MAE/RMSE) | CORRELATION_OK |
| ⑥ ECO・テストプログラム | 変更影響分析 → ECOクローズ → **マスク/テストプログラムリビジョン増加 + エビデンス再承認強制**(§14.3) | ECO_CLOSED |
| ⑦ CS・量産前信頼性 | AEC-Q100 Grade別温度条件テーブル(`alps-asic-v1.0`ポリシー)、エビデンス/CAPA/ウェイバー | QUAL_PASS |
| ⑧ リリース・エビデンス | エビデンス電子署名、readiness ladder(education_only→released)、ゲートJSON | EVIDENCE_APPROVALS |
| ⑨ 量産 | ロットSPC・パレート、不良ロットMRB処分、出荷 | LOT_RELEASE |

- 4つの製品テンプレート(静電容量タッチAFE/電流センサー/モーターリプル/環境センサー)× 異なるゲート状態・ミッション・相関パラメータ。
- ステージコックピット: 進行段階n/9、次ゲート、カバレッジ、良品率、R²を一目で。
- **設備ラックストリップ**: 設備ランパネルの上にラン状態LED+校正カウントダウンバー(calibration_expires_at)+findingsチップを表示。
- ゲートJSONがブロッカー(`MOCK_RESULT_PRESENT`、`EVIDENCE_APPROVALS`等)と`decision_required`を誠実に出力 — **リリースは偽って押されない**。

**v1.1拡張 (バックエンド連携 — 仕様書v1.1 §4/§7/§8、電流センサーASIC PoC)**

- **信号チェーンリビジョン (EPIC A)**: r1→r2の昇格は修正ではなく新リビジョン生成+旧リビジョンのsupersede(不変ルール)。ブロック別エラーバジェット表とcontent_hashを②③段階に表示。
- **Corner/MC解析 (EPIC A)**: シード固定のエラーバジェット伝搬モンテカルロ → P50/P95/P99・規格逸脱率+**実サンプル24-binヒストグラム**。試験温度が校正範囲外ならMODEL OODバッジ。同一シード=同一結果(再現性 §12)。
- **設備実測インポート (EPIC E)**: テスターCSVの生バイトをパース前にsha256アーティファクトへ昇格。**同じファイルが2つのランになることはない**(409)。部分ファイル・時間逆転・重複ブロックはfindingsとして記録(無音修正禁止 §7)。校正期限はデータとして保存され、ゲートブロッカーになる。
- **信頼性マトリクス+閉ループ (EPIC F・G)**: AEC-Q100はグループごとに最新行で判定。不合格行はFAケースで処分 — RCA承認は**人間専任ロールのみ**で、観察事実+確認エビデンスがなければ422。ECOはリグレッションエビデンス+検証測定ランなしで終了すると412。終了時にFAはverifiedへ移り閉ループ。
- **機能安全トレース**: SG→FSR→TSR→HWツリー+FMEDA(分布・DC・FIT・ソースハッシュ)+故障注入(期待/観察)を⑦段階に描画。
- **ゲートポリシー `alps-asic-v1.1`**: 新ブロッカー `CALIBRATION_EXPIRED`・`MODEL_OOD`・`MIXED_REVISION_EVIDENCE`・`QUAL_FAILURE_OPEN`・`WAIVER_EXPIRED` + 不変の`MOCK_RESULT_PRESENT`。Readiness Ladder 6段階(education_only→…→controlled_pilotまで到達可、production_candidate/releasedは未到達)。**ゲートレポートはサーバー値をそのまま描画** — UIがブロッカーを生成しない。
- 書き込みはすべてロールゲート(インポート=試験、RCA=ASIC/品質エンジニア、ECO終了=アーキテクト/承認者)。バックエンドの韓国語デモ文字列は描画時のl10nオーバーレイでen/ja表示。

**v1.1 R2拡張 (仕様書§10 — ファウンドリ・パッケージ・テストプログラム・エビデンス)**

- **トレードスタディ (EPIC B)**: プロセス・パッケージ選択肢のNRE/単価/リードタイム加重スコア。未確定の軸は0として計算せず、部分スコア+TBD軸名を明示。決定は根拠・残存リスクとともに記録され、金額はCAN_COSTロールにのみ表示。③段階。
- **EDA ToolRun (EPIC C)**: `real_adapter`実行はツール出力のsha256+lineageを要求し、`mock`実行はゲートブロッカー(`MOCK_RESULT_PRESENT`)として正直に残る。④段階。
- **テストプログラムツイン (EPIC D)**: wafer_sort/final_testフロー別の項目・時間・カバレッジ+**クロスターゲット分析**(同一limitsの重複はdrop候補、カバレッジ空白を表示 — レビュー専用、自動適用なし)。サイト時間あたりレート未確定フローの原価はnull(TBD) — 0として計算されない。⑥段階。
- **サプライチェーン・ロット系譜 (EPIC H)**: ファウンドリ/OSAT/subconパートナー状態、PCN変更追跡、シリコン・マスク・パッケージリビジョンを伴うロットトラベラー、ウェハーマップの歩留まり/再試験率+overkill/underkill(source_classチップ付き)。⑨段階。
- **製品検証パック (P1-07)**: 4製品テンプレート専用シード — 電流センサー(Template B)はR1+R2全閉ループ、A/C/Dは検証パック(信号チェーン・トレードスタディ・テストフロー)。
- **エビデンス報告書 (P1-08)**: `GET /asic/templates/{id}/evidence-report?lang=ko|en|ja` — 設計・実測・認証・安全・テスト・サプライチェーン・ゲート全セクションを3言語で。金額は含まず(CAN_COSTビュー専用)、TBDは名前を明示し、SYNTHETIC/MOCKソースはどの言語でも実測値として読めない。パネルはUI言語に自動追従。

### 3.10 結果比較・相関・ゲート (下部フレーム)

- **Gate (S10)**: ゲート提出/審査ステータス。

## 5. 既存ソリューションとの差別化

| 比較対象 | 既存方式の限界 | 本システムの差別化ポイント |
|---|---|---|
| 伝統的PLM(ドキュメント中心) | 3D・シミュレーション・判定がツールごとに分散、ドキュメント登録が目的 | **ライブツイン+エビデンスチェーン統合** — 見ている画面がそのまま証拠 |
| 単体シミュレーター(SPICE/FEMツール) | 結果がワークベンチ外のファイルとして存在、要求と断絶 | ラン結果が要求・ゲート・相関パネルと即時接続 |
| Unity等ゲームエンジンデジタルツイン | ランタイムインストール・ライセンス・Webデプロイ負担、IT協議必要 | Web標準のみで3D実装 — **Unity依存なし**(開発指示書要件を充足) |
| Excel/メールベースASIC進行管理 | 段階・ゲート・エビデンス・ECO状態が人の頭の中に存在 | 9段階ワークセンターがゲート・ブロッカー・エビデンスリビジョン・ECOを1画面で強制 |
| 社内教育(ドキュメント+試験) | 実習環境不在、実機材誤操作リスク | **実サインオフと物理的に分離された**研修モジュール(EDA・ASIC) |
| 汎用BIダッシュボード | ステータス表示のみ可能、行動誘導不可 | 各指標からすぐ次のアクション(承認・MRB・ECO)につながるワークフロー |

核心的な差別化ポイントは**「誠実性がシステムに内蔵」**されている点である — 教育/デモ用結果が実際のリリース判断に流れる経路を構造的に遮断(`MOCK_RESULT_PRESENT`不変ブロッカー、到達不可readinessレベル✕表示、承認エビデンス不変ルール)するため、デモ用環境と実務ゲートが同じツール内に共存できる。

## 6. Alps Alpineでの活用可能性

1. **製品ポートフォリオ1:1テンプレート** — タクトスイッチ、近接/エアインプットセンサー、電流センサー、モーターリプル、環境センサー、静電容量タッチAFE ASICがすでにテンプレートとして存在。新規製品はテンプレート複製で開始。
2. **部門横断の単一画面** — 営業(要求)、設計(3D・EDA)、品質(ゲート・MRB・SPC)、生産(プロセスツイン)が同一データを見ながら各々のビューで作業。
3. **ASIC受託/自社開発管理** — 9段階ワークセンターで顧客・協力ファウンドリとの段階別エビデンス(スペックベースライン、ES相関、ECOリビジョン、AEC-Q100認証)を追跡。
4. **新入/中途エンジニアオンボーディング** — EDA研修(組合せ・順序・プロトコル・RISCミッション)とASIC 9段階シミュレーションで、実開発データに触れない安全な実習。
5. **顧客レビュー会資料** — 3D爆発図・波形・相関グラフをブラウザで即デモ、コンフィデンシャル分類表示で情報等級管理。
6. **教育→実務移行経路** — 研修モジュールで学んだランナー・ゲート概念が実務ワークセンターと同一UIのため学習コスト最小。
